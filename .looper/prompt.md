# Full gates use ~1.5 of 16 CPUs: run independent gates and cross-test legs concurrently (bounded), keep the verdict deterministic

**The full gates use about 1.5 of 16 CPUs: a land takes hours because gates run serially.** (Jody, 2026-11-03: "I just want stuff to go faster and my gut instinct is much of this can be done in parallel.")

**Evidence:**
- #256's land started at 01:24:06Z (looper job 17682...; see #256's issue) and was still running at 07:02Z, **5.5 hours**.
- On its runner (`runner-arm64-tacplus-big-…`, t2a-standard-16, 64 GB) at 07:02Z: **load average 1.78, 1.51, 1.42.** One `rustc` and one `cargo test -p diskstore` were running. Disk was 49% used.
- The VM was added for parallel children (looper#55). A land runs alone, and leaves 14 of 16 CPUs idle.

**Fix: run independent gates and legs concurrently, bounded by the machine:**
1. `just gates`: the gate list is a set of independent recipes (protoc-check, soundness, test, current-generation, determinism, cert-stream, memberport, claims-provenance, c2d-server, zero-rpc-s2s, jwk-alg, stream-expiry, tacplus-script, …). Run them as a DAG with a concurrency cap (`GATES_JOBS`, default = CPUs / 2). Keep the output per gate, and keep `=== OVERALL fail=N ===` and each gate's `rc=` lines exactly as they are. Order only where a gate really needs another's output.
2. **Inside cross-test runners** (current-generation and friends), run fixtures and language legs in parallel with the same cap. Each leg uses its own target directory, so legs don't contend for cargo's lock. #282's pruning keeps disk bounded.
3. **Determinism:**
   - the verdict and each gate's result must not depend on the order;
   - the gate log is assembled in a fixed order;
   - a test runs the gates twice with different caps and gets the same verdict.
4. **Measure:** the gate summary prints each gate's wall time and the total. The nightly recap (looper#57) reports land time per gate set, so the gain is visible.

**Expected:** with 16 CPUs and the current list, the full gates should drop from hours to well under one, bounded by the longest single gate. The gate times from step 4 will confirm it.
